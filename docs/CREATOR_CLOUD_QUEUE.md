# Creator server queue

The review page now has independent Start 24 hours, Run 24/7, and Pause controls. These configure a persistent Supabase queue; they do not rely on a Codex conversation or open browser. The existing browser helper is separate and requires an available PC for sites needing authenticated playback.

The selected mode is visibly highlighted with an accessible 24/7 switch. A status panel distinguishes pause, startup, portfolio discovery, video analysis, provider waiting, stale scheduler heartbeat, and an exhausted hourly quota. The hourly budget bar/countdown is separate from the successfully verified progress bar: blocked jobs never inflate completed reviews. Counts refresh every15 seconds; the countdown is local and generates no extra API calls. Mode changes show immediate saving/success/error feedback; stale polling responses cannot overwrite a newer selected mode. Only task IDs and phase labels are exposed for in-flight work, not provider URLs or credentials.

`creator-cloud-review` runs every minute through pg_cron/pg_net. It wakes only the fixed production `/api/creator-review/cloud-tick` route. The URL uses a dedicated HMAC derived on the server, stored in server-only settings, never returned to the client. A database advisory lock, unique hourly creator claims and six-minute leases cap dispatch at 20 distinct creators per UTC clock hour and two concurrent jobs. The existing media API additionally enforces its own free-provider budget. A running provider request may finish after Pause. No subscription or billing settings changed.

The worker reads the canonical Reddit directory, uses public Drive/YouTube/media and discovers embedded files from public portfolio HTML. Public Canva portfolios additionally render in Chromium on Vercel, using the standard puppeteer-core and @sparticuz/chromium packages; no browser subscription, PC process or cookie export. It resumes cached media from the same creator. DNS/public-host checks, bounded HTML, restricted redirects/GET-only browser requests, two sample attempts and source-fingerprint checks fail closed. No PC media downloads. Authentication-only playback and inaccessible Drive files remain blocked with a reason; this is not a guarantee that all remaining applicants can be fully reviewed unattended. Attempts are shown separately from successful audio/video completion. There is no guaranteed 20 successful reviews per hour.

Results require both original speech and visual evidence. They are saved as proposals in the existing creator directory. Strong candidates default to yellow pending quality/value confirmation; poor actual speech/video may be red. No universal price cutoff. Owner choices remain separate. Older Site snapshots cannot overwrite a newer source-matched autonomous assessment. No worker path imports contacts or sends creator emails. Exact campaign approval remains separate.

The worker checks submitted social links when portfolio video is unavailable. For TikTok profiles it uses the public creator embed and selects video entries that identify the submitted handle and are marked public. Signed CDN URLs feed the existing video analysis pipeline without saving local media. Instagram post metadata can provide video, while an Instagram profile that does not expose its posts may require a public Reel URL or another portfolio sample. Keep access failures visible and count only persisted audio and video reviews as completed.

Reddit cards resolve submitted TikTok profiles on demand and use the existing TikTok player. New reviews store the exact post URL. Historical reviews show a verified badge only when the reviewed CDN asset matches a post in the public profile embed. Public covers are snapshotted to the private `creator-tiktok-covers` bucket (migration 0010) and served to signed-in users. The 256 KiB limit applies to images only. Cover failure does not block playback or review.

Migration 0007 is additive and creates isolated tables/functions plus one cron job. Backup existing directory through the normal project backup policy before modifying existing data. The migration itself does not rewrite directory rows. Rollback: Pause, `cron.unschedule('creator-cloud-review')`, revert code; keep queue/history tables for audit. Never undo existing creator correspondence or approved imports. Inspect cron.job_run_details, queue leases/status/error and Vercel failures to distinguish scheduler success from provider success. Renewed form sources can be queued with Start; blocked unchanged sources require a usable video rather than endless retries.

Validation: fixture tests for source binding, incomplete modalities, and stale snapshot merge; full npm test and typecheck. Production acceptance additionally requires an actual scheduled tick, claimed jobs and persisted results/errors with no active browser/chat trigger.
